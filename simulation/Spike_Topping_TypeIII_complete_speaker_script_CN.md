各位老师好。今天汇报的是伴随重联喷流发生的 Spike-Topping Type III

## 第 2 页：研究动机（约 60 秒）

Type III 主脊反映快速电子束沿密度递减方向传播，提供快速射电时标。起始端
高频 spike 则可能约束电子注入的时刻以及相对于主脊的频率位置。

如果只在动态谱上任意叠加亮点，无法检验它是否与磁重联或 jet 有关。因此本
项目把问题改写成可证伪条件：spike 必须在 Type III 起始窗内，必须满足
\(\Delta f=f_{\rm spike}-f_{\rm III}(t)>0\)，并且所在时刻的 jet 和重联
活动都要超过预先固定的门槛。

这里以 2025-01-24 作为后续事件约束方向，但当前阶段仍是机制约束的前向
模拟，不声称完成观测反演。

转场：为了避免不同模型层次相互混淆，项目采用分层架构。

## 第 4 页：RMHD 方程和数值方法（约 90 秒）

二维磁场和速度分别由磁通函数 \(\psi\) 与流函数 \(\phi\) 表示：

\[
\boldsymbol B=\nabla\psi\times\hat{\boldsymbol z},\qquad
\boldsymbol v=\nabla\phi\times\hat{\boldsymbol z}.
\]

因此涡量和电流为

\[
\omega=\nabla^2\phi,\qquad j=\nabla^2\psi.
\]

采用的演化方程是

\[
\frac{\partial\omega}{\partial\tau}+[\phi,\omega]
=[\psi,j]+\nu\nabla^2\omega,
\]

\[
\frac{\partial\psi}{\partial\tau}+[\phi,\psi]
=\eta\nabla^2\psi.
\]

空间使用 FFT 伪谱法，所有二次非线性项执行严格的
\(|m|<N/3\) 掩膜，时间使用经典 RK4。正式结果使用
\(\Delta t=0.00125\)、\(\eta=\nu=0.002\)。

这种表示自动满足二维无散结构；正式 CPU 结果的归一化
\(\nabla\cdot\boldsymbol B\) RMS 为 \(3.74\times10^{-14}\)。

转场：有了场和流之后，下一步是把“jet”定义成可计算的诊断量。

## 第 5 页：jet 与重联诊断（约 60 秒）

这里不把单个速度峰直接称为 jet。程序在两条 Harris 片层附近分别寻找正向
与负向 outflow，计算两侧速度的 95% 分位，并取两者较小值：

\[
v_{\rm bi}(t)=\min\!\left[
P_{95}(v_{\rm out}>0),P_{95}(-v_{\rm out}<0)
\right].
\]

这样只有持续的双向 outflow 才能提高 jet 活动 \(q_J\)。重联活动记为
\(q_R\)。两者均达到 0.6，并连续保持 3 个快照，才允许定义 onset。

这一定义刻意排除了单向局部噪声和单快照峰值。

转场：射电 spike 还要在这个物理窗口内满足严格 topping。

## 第 6 页：严格 topping 条件（约 60 秒）

联合活动权重定义为

\[
q_{\rm joint}(t)=q_J(t)q_R(t).
\]

spike 只能在有效连续区间中按这个权重抽样。射电时间窗为

\[
t\in[0.08,\min(0.75,0.25T)]\ {\rm s},
\]

并强制使用正频偏：

\[
\Delta f=f_{\rm spike}-f_{\rm III}(t)>0.
\]

catalog 保持五列结构。若不存在同时满足 \(q_J\)、\(q_R\)、连续性、起始窗
和正频偏的候选，返回形状为 `(0,5)` 的空 catalog，并记录 `no_event`。

转场：为了比较 CPU 与 CUDA，所有科学参数必须完全相同。

## 第 12 页：数值验证（约 60 秒）

## 第 14 页：CPU/CUDA 正式对照（约 60 秒）

服务器 CPU 的求解时间为 976.85 秒，4K 渲染为 4173.70 秒。WSL2 RTX 4060
Laptop 的求解时间为 187.95 秒，渲染为 2348.02 秒。

因此 CUDA 的求解加速为 5.20 倍，包含渲染的总流程加速为 2.03 倍。两者都

标量最大绝对差异不超过 \(1.34\times10^{-15}\)。

这个比较说明 CUDA 提升了 Torch RMHD 的效率，而不是改变了科学结论。也
不能据此声称 Athena 4.2 或 AMRVAC 已有 GPU 加速。

## 第 15 页：结论与下一步（约 60 秒）

本阶段有三点结论。

第一，严格 jet/reconnection 条件下得到 12 个起始高频 topping 事件，而
control 合法返回 `no_event`。

第二，无散、能量预算、空间收敛、时间步收敛、跨 CPU 分区和 CPU/CUDA 一致性

第三，可信结论仍限于二维不可压缩 RMHD 与现象学射电代理。它不能替代真实
2.5D 日冕 jet、等离子体自洽辐射或事件反演。

再加入开放场、重力分层、导引场、热传导和 600 秒演化，并与 2025-01-24

## 常见问题

### 1. 为什么先用 RMHD，而不是直接运行完整 2.5D？

RMHD 可以低成本验证符号、谱离散、jet 条件、射电逻辑和跨平台一致性。完整
2.5D 在静水平衡、开放边界、无散控制和热物理上更容易产生伪流；当前
Athena 4.2/AMRVAC smoke 的失败门槛证明不能跳过静态基准。

### 2. 总能量下降 6.69% 是否说明计算不稳定？

不是。模型显式包含电阻与黏性，能量可以耗散。稳定性与守恒质量由离散能量
预算残差、有限性、收敛和无散诊断共同判断；本轮预算残差为
\(3.14\times10^{-8}\)。

### 3. 12 个事件是否由人为降低阈值得到？

不是。\(q_J\ge0.6\)、\(q_R\ge0.6\)、连续 3 个快照、起始窗和
\(\Delta f>0\) 均为固定条件。control 使用相同门槛并返回 `no_event`。

### 4. CPU 与 CUDA 为何能得到相同结果？

两者使用相同源码、同一 seed、float64、相同 FFT/RK4 和相同配置；CUDA 关闭
TF32 与 AMP。剩余差异处于浮点舍入量级，事件分类和 catalog 一致。

### 5. 为什么 CUDA 只快 5.20 倍，而不是更高？

本任务包含双精度 FFT、数据传输、HDF5 与 Python 调度。RTX 4060 Laptop 的
双精度吞吐并非面向科学计算卡设计。渲染又包含大量 CPU 绘图和视频编码，
因此总流程加速只有 2.03 倍。

### 6. 这里的 jet 与真实日冕 jet 有何差别？

当前 jet 是二维周期电流片附近的局部双向重联 outflow。真实日冕 jet 是沿
开放磁场传播、具有密度、压力、三分量速度磁场和热力学结构的全局喷流。

### 7. Athena、AMRVAC 和 RMHD 的结果能否逐像素比较？

不能。三者方程、变量、网格和数值耗散不同。应比较初态拓扑、onset 顺序、
活动曲线、守恒诊断和事件分类，而不是要求逐像素相同。

### 8. 2025-01-24 事件目前用了哪些信息？

目前只作为下一阶段的观测约束方向。核心射电窗、频率范围和 AIA/射电几何应
通过去隐私化 EventBundle 输入；当前 12 个事件不是该真实事件的拟合结果。

### 9. 为什么服务器 Python 任务不使用 MPI？

现有 Python RMHD 没有域分解。用 `mpirun` 会启动多份独立相同任务，既浪费
资源又可能覆盖输出。并行性来自 FFT/Torch 和底层线程；MPI 留给 Athena 或
AMRVAC 的原生并行求解器。

### 10. 下一项最重要的工作是什么？

先使无驱动 2.5D 静态模型满足低 Mach、无散和 restart 门槛，再做驱动 jet、
热传导和 600 秒演化。只有这些门槛通过后，才应进入事件扫描和观测比较。
