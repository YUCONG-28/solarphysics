Running the Athena 4.2 flux-rope demo on a Slurm cluster

Privacy note
------------
Do not store passwords, private IP addresses, user names, host names, or
personal absolute paths in this file. Use the site-specific values only in
your terminal or private SSH configuration.

1. Log in using the account and host supplied by the cluster administrator:

   ssh -p <PORT> <ACCOUNT>@<CLUSTER_HOST>

2. Upload the reviewed `simulation/fluxrope_demo/` directory to a private
   cluster working directory. The canonical project source is already located
   in:

   fluxrope_demo/athena4.2/

   The historical `athena4.2.tar.gz` is retained only as upstream provenance;
   do not extract it over the canonical project source.

3. Load a supported C compiler. Module names differ by cluster, for example:

   module purge
   module load <GCC_MODULE>

4. Build in a private scratch copy so generated Makefiles, objects, logs, and
   binaries do not enter the canonical source directory:

   cp -R fluxrope_demo/athena4.2 <PRIVATE_SCRATCH>/athena4.2-fluxrope
   cd <PRIVATE_SCRATCH>/athena4.2-fluxrope
   CC=gcc ./configure --with-problem=fluxrope --with-gas=mhd \
     --with-eos=adiabatic --with-integrator=ctu --with-order=2 \
     --with-flux=hlld
   make all

5. Prepare a private run directory:

   mkdir -p <PRIVATE_SCRATCH>/run_case_01
   cp <UPLOADED_FLUXROPE_DEMO>/athinput.fluxrope <PRIVATE_SCRATCH>/run_case_01/
   cp bin/athena <PRIVATE_SCRATCH>/run_case_01/
   cp <UPLOADED_FLUXROPE_DEMO>/job_serial <PRIVATE_SCRATCH>/run_case_01/
   cd <PRIVATE_SCRATCH>/run_case_01

6. Review the grid and runtime in `athinput.fluxrope`, then submit and monitor:

   sbatch job_serial
   squeue
   scancel <JOB_ID>

7. Download only reviewed result files. Use
   `plot_var_fluxrope_tutorial.ipynb` for the historical VTK demonstration.

For Spike-Topping production builds, use the Python Athena workflow documented
in `simulation/README.md`; raw BIN/VTK/HST data remain under `Local/athena/`.
